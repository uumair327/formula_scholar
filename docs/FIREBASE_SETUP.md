# Firebase Setup

This project uses Firebase for authentication and data storage. The repository ships with generated configuration files for the current project, but contributors should know how to refresh them and how to keep secrets out of source control.

## What Is Safe To Commit

- Firebase API keys and app IDs generated by FlutterFire
- `firebase.json`
- Project-specific configuration files that do not contain admin credentials

## What Must Stay Private

- Firebase Admin SDK service-account JSON files
- Private signing keys and keystores
- Local `.env` files

## Local Setup

1. Install the FlutterFire CLI if you do not already have it.
2. Run `flutterfire configure` from the project root when you need to regenerate Firebase platform config.
3. Copy `.env.example` to `.env` and fill in only local values.
4. Store the Firebase Admin SDK JSON outside the repository and set `FIREBASE_SERVICE_ACCOUNT_PATH` when running the maintenance scripts.

## Android

- `android/app/google-services.json` is generated by FlutterFire for this project.
- If you need to regenerate it, run `flutterfire configure` and choose the Android target.

## Dart / Flutter

- `lib/firebase_options.dart` is the FlutterFire-generated options file used by `main.dart`.
- Contributors who regenerate Firebase config should keep the generated file in sync with the app settings.

## Admin Scripts

The scripts in `bin/`, `scripts/`, and `firestore-seeder/` read credentials from either:

- `FIREBASE_SERVICE_ACCOUNT_PATH`
- the first command-line argument

This keeps service-account files out of the repository while still allowing local maintenance.

## Troubleshooting

- If Firebase initialization fails, verify that the app-specific config files match the active Firebase project.
- If admin scripts fail, confirm that the service-account JSON path is valid and readable.
