# 🚀 Golden Rules for Agentic AI Vibe Coding (Flutter) — Production Standard

---

## 1. 🧠 Architecture is a Contract

* Follow strict dependency flow:
  presentation → domain → data
* UI depends only on UseCases
* Domain has zero external dependencies
* Data implements domain contracts

Rule:
If UI imports Dio or API → architecture is broken

---

## 2. 🧩 SOLID is Mandatory

* S: One class = one responsibility
* O: Extend, don’t modify
* L: Replaceable implementations
* I: Small interfaces
* D: Depend on abstractions

Rule:
If a change requires editing 3+ files → design is wrong

---

## 3. ⚡ Predictable State Management

* Cubit → simple UI state
* Bloc → complex flows (API, pagination)

Rules:

* One feature = one source of truth
* No duplicate state
* No business logic in UI

---

## 4. 🌐 API Layer Must Be Swappable

Structure:
UI → UseCase → Repository → DataSource → ApiClient

Rules:

* No Dio outside data layer
* Use interceptors (auth, retry, logging)

Rule:
If replacing Dio breaks app → abstraction is wrong

---

## 5. 🧱 Dependency Injection (injectable + get_it)

* No manual wiring
* No `new` inside business logic
* All dependencies injected

---

## 6. 📦 Feature = Mini App

Structure:
feature/
module/
presentation/
domain/
data/

Rules:

* Barrel exports only
* No cross-feature imports
* Feature should be portable

---

## 7. 🎯 No Magic Values

Centralize:

* AppColors
* AppDimens
* AppDurations
* AppStrings
* AppAssets

Rule:
No hardcoded strings or numbers in UI

---

## 8. 🧾 Logging = Observability

Log:

* API requests/responses
* Errors
* Bloc state changes

Rule:
Debug any issue within 10 seconds using logs

---

## 9. 🧭 Routing = Pure Navigation

* Use go_router
* No business logic in routes
* Typed navigation only

---

## 10. 🔐 RBAC Enforcement

Apply at:

* UI (hide features)
* Bloc (block actions)
* UseCase (final enforcement)

Rule:
If API works without permission → RBAC is broken

---

## 11. 💾 State vs Cache Separation

* HydratedBloc → UI/session state
* Hive → data caching

Rule:
HydratedBloc ≠ database
Hive ≠ state manager

---

## 12. 🔄 Pagination Must Be Deterministic

* No client-side filtering after pagination
* No duplicate records
* Immutable list updates only

---

## 13. 🌐 Network Handling First-Class

Handle:

* No internet
* Timeout
* Retry
* Fallback

Rule:
App must never fail silently

---

## 14. 🤖 Agent-Friendly Code

* Small files (<200 lines)
* Clear naming
* Explicit logic
* No hidden magic

Rule:
Code should be understandable instantly by dev or AI

---

## 15. 🧪 Testability by Design

Test:

* UseCases
* Repositories

Rule:
If testing is hard → architecture is wrong

---

## 16. 🧹 Consistency > Intelligence

* Same naming patterns everywhere
* Same folder structure
* Same patterns

Rule:
Predictable code > clever code

---

## 17. 🔁 State Lifecycle Discipline

Handle:

* init
* loading
* success
* failure
* refresh
* dispose

Rule:
No stale or ghost state

---

## 18. 🧨 Side Effects Isolation

Examples:

* navigation
* dialogs
* snackbars

Rule:
Bloc emits state → UI handles side effects

---

## 19. ⚙️ Feature Toggle Ready

Support:

* feature flags
* role-based access
* remote config

---

## 20. 🚫 Anti-Patterns to Avoid

* God Bloc
* Direct API in UI
* Mutable state
* Global variables
* Overuse of HydratedBloc
* Copy-paste logic

---

# ⚡ Final Checklist

Before shipping:

* API layer replaceable
* UI has zero business logic
* State predictable and minimal
* No magic values
* RBAC enforced
* Logs sufficient
* No stale state
* Pagination correct
* Code easy to understand

---

# 🧠 Final Truth

Tools don’t scale systems.
Discipline does.
